PREGUNTA 1 — PHP Y LARAVEL
===============================================================================

¿Cuál es la diferencia entre PHP y Laravel?

Explica:

- qué es PHP;
- qué es Laravel;
- qué proporciona Laravel sobre PHP;
- al menos cuatro funcionalidades propias de Laravel;
- un caso en el que usarías PHP sin framework;
- un caso en el que elegirías Laravel;
- si es posible utilizar Laravel sin conocer PHP y por qué.

RESPUESTA:
1. ¿Qué es PHP? Es un lenguaje de programación de código abierto, con tipado dinámico (por defecto no es necesario declarar el tipo de dato de una variable),
aunque en las últimas versiones del lenguaje tiene de manera opcional definiciones de tipo.
Es un lenguaje interpretado de servidor ya que su ejecucion se realiza en el servidor web antes de mostrar el 
resultado final al usuario.

2. ¿Qué es laravel? Es un framework open source para PHP diseñado bajo el patrón
Modelo-Vista-Controlador(MVC) con el fin de facilitar el desarrollo web, proporcionando
un conjunto de herramientas dentro de su propio ecosistema.

3. ¿Qué proporciona Laravel sobre PHP? Siendo PHP la base de Laravel, éste proporciona una arquitectura modular y estructurada. Permitiendo así  
abstraer funcionalidades y tareas repeptitivas que con PHP puro se tendrían que hacer desde cero.

4. Al menos cuatro funcionalidades propias de Laravel
    4.1. Su propio ORM(Object-Relational Mapping) llamado Eloquent que permite mapear la base de datos, definir sus relaciones y manejar las tablas de la
    base de datos como código PHP.
    4.2. Motor de plantillas Blade, permite combinar código HTML y PHP en un mismo archivo para así compilarse en el mismo PHP
    4.3. La consola de comandos Artisan, permite generar código base (modelos, migraciones, controladores, etc)
    4.4. Procesamiento HTTP y filtrado a través de los Middleware que permite filtrar y autenticar peticiones enviadas a los controladores.

5. Un caso en el que usaría PHP sin framework, lo usaría en el caso de ejecución de scripts para correr en consola de comandos del SO 
así como para el desarrollo de plugins en CMS como Wordpress

6. Un caso en el que elegirías Laravel, para creación de API's o aplicaciones web un poco más complejas y que puedan escalarse de una forma más sencilla

7. ¿Es posible utilizar Laravel sin conocer PHP y por qué? No es posible usar laravel sin tener un conocimiento previo de PHP porque si bien Laravel proporciona 
una capa de abstracción, tood está hecho con PHP y el desarrollo de la aplicación se hace es con PHP (modelos, controladores, rutas). No se debe ser un experto en PHP
pero sí se deben tener conocimientos base de PHP y de programación orientada a objetos.

PREGUNTA 2 — ESTRUCTURAS DE DATOS
===============================================================================

Selecciona la estructura de datos más apropiada para cada caso:

1. Procesar solicitudes en el orden en que llegaron.
2. Implementar la función "deshacer" de un editor.
3. Buscar rápidamente un usuario mediante un identificador único.
4. Representar las conexiones entre usuarios de una red social.

Para cada caso explica:

- la estructura elegida;
- cómo funciona;
- el costo aproximado de insertar, buscar o retirar elementos;
- una alternativa y por qué sería mejor o peor.

RESPUESTA:

1. Procesar solicitudes en el orden en que llegaron.
    La estructura que se utilizaría es una COLA, ya que ésta usa el principio FIFO (first in, first out)
    osea primer elemento que entra, primero que sale. Tiene dos funciones principales "encolar" y "desencolar"
    que son las encargadas de insertar y eliminar elementos bajo el principio FIFO
    Tiene un orden de ejecucion constante O(1) para "encolar" y "desencolar" y O(n) para realizar búsquedas
    La variante podria ser una lista simple enlazada pero no seria una mejor alternativa ya que este tiene un 
    orden de ejecucion n O(n) y como la lista trabaja con punteros guardar un nuevo elemento representaria recorrer TODA
    la lista nuevamente.
2. Implementar la función "deshacer" de un editor.
    La estructura que usaría es una PILA, ya que ésta usa el principio LIFO (last in, first out) osea el último
    elemento que se ingresó será el primero en salir. Tiene dos funciones principales "push" para insertar elementos y "pop"
    para desapilar elementos. Tiene un orden de ejecucion constante O(1) para "push" y "pop" y O(n) para realizar búsquedas
    Una variante interesante podría ser una lista doblemente enlazada ya que esta posee dos nodos uno previo y uno siguiente y permitiría
    una búsqueda en ambas direcciones tanto para atrás como para adelante pero como consumiría mayor cantidad de memoria porque tendría que almacenar dos nodos
    así que en cuanto a rendimiento sería peor.

3. Buscar rápidamente un usuario mediante un identificador único.
    La estructura a utilizar sería una tabla Hash o Diccionario, ya que cada registro de usuario se guarda y vincula a un identificador único
    siendo éste su clave y como la gran particularidad de la tabla hash es que tiene una función matemática que permite acceder de forma directa a la 
    posición del elemento en arreglo.
    El orden de ejecución de la tabla hash es de O(1) tanto para buscar, eliminar y agregar
    La variante a utilizar acá sería un árbol binario balanceado, ya que se mantendrían las claves ordenadas y las búsquedas serían más eficientes.

4. Representar las conexiones entre usuarios de una red social.
    La estructura a utilizar sería un grafo, ya que estos son estructuras de datos compuestos de nodos y vértices
    y también aristas las cuales pueden ser dirigidas o no dirigidas, estas se pueden representar con una matriz de adyacencia 
    o una lista de adyacencia. Ésta es la estructura que de por sí se suelen usar en las redes sociales.
    Tiene un orden de ejecución para insertar aristas y vértices de O(1) pero para búsquedas implica un O(grado(v)) dependiendo del
    grado del vértice.

    Quizá una alternativa pueda ser una tabla hash pero de set o sea de conjuntos ya que permitiría verificar relaciones en tiempo constante
    o sea un orden de ejecucion O(1) pero igualmente dependería de la cantidad de datos ya que esta estructura consume más memoria

Implementa la siguiente función PHP:

function countWords(string $text): array

La función debe:

- ignorar signos de puntuación;
- separar las palabras aunque existan varios espacios;
- ignorar elementos vacíos;
- contar cuántas veces aparece cada palabra;
- ordenar el resultado de mayor a menor frecuencia;
- en caso de empate, ordenar alfabéticamente;
- devolver un arreglo asociativo.

Ejemplo:

$text = 'PHP es útil. Laravel usa PHP; PHP es un lenguaje.';

Resultado esperado:

[
    'php' => 3,
    'es' => 2,
    'laravel' => 1,
    'lenguaje' => 1,
    'un' => 1,
    'usa' => 1,
    'útil' => 1,
]

Explica:

- las funciones de PHP que utilizaste;
- cómo manejaste la puntuación y los espacios;
- qué sucede si el texto está vacío;
- cómo harías que funcione correctamente con Unicode y acentos.

RESPUESTA:

function countWords(string $text): array
{
    if(trim($text) === '') {
        return [];
    }

    $text_lower = mb_strtolower($text, 'UTF-8');
    $words = preg_split('/[^\p{L}\p{N}]+/u', $text_lower, -1, PREG_SPLIT_NO_EMPTY);
    $incidences = array_count_values($words);

    uksort($incidences, function (string $a, string $b) use ($incidences): int {
        if ($incidences[$a] !== $incidences[$b]) {
            return $incidences[$b] <=> $incidences[$a];
        }
        return strcmp($a, $b);
    });
    return $incidences;
}

$resultado = countWords('PHP es útil. Laravel usa PHP; PHP és un lenguaje.');

echo '<pre>';
print_r($resultado);
echo '</pre>';

- Funciones PHP
    * mb_strtolower: es una función para convertir el texto en minúsculas.Se pudo utilizar 
    strtolower pero entonces las vocales mayúsculas no las iba a tomar en cuenta al momento
    de pasarla a minúsculas y luego no se tomarían en cuenta para el conteo.
    
    * preg_split: recibe como parámetros una expresión regular que separa el texto si encuentra algo 
    que no es una letra o un numero, además que indica que el patrón debe interpretar el texto como UTF-8
    otro parámetro que recibe es el texto y una bandera que le indica al método que ignore cual espacio o fragmento
    vacío resultante.
    * array_count_values: cuenta la cantidad de veces que aparece cada elemento y crea el arreglo asociativo

    * uksort: ordena el arreglo asociativo  funciones anónimas comparando de mayor a menor
    y en caso de empate usa el método strcmp() para ordenarlo por orden alfabético.
    * print_r: imprime el arreglo resultante en pantalla.

- Cómo se manejaron la puntuación y los espacios
    * Con la expresión regular en el preg_split /[^\\p{L}\\p{N}]+/u donde \p{L} que permite la 
    coincidencia con cualquier letra en cualquier idioma y \p{N} permite la coincidencia con cualquier
    número y el símbolo de ^ selecciona cualquier conjuto de caracteres que no sean letras ni números
- ¿Qué sucede si el texto está vacío?
    Al inicio de la función se hace esta validación con el if(trim($text) === '') {
        return [];
    } el cual simplemente pregunta si el texto viene vacío de ser así solo retorna un arreglo vacío.

- ¿Cómo haría que funcione correctamente con Unicode y acentos?
    Si quiero que ignore los acentos y lo tome como igual con respecto a las que no tienen entonces
    tendría que normalizar el texto pero para esto debo tener una extensión habilitada. Para el caso de Unicode 
    ya está implementado con el mb_strtolower para usarla se debe habilitar la extensión mbstring dentro del 
    php.ini

===============================================================================

Considera estas tablas PostgreSQL:

users
-----
id          BIGINT PRIMARY KEY
name        VARCHAR(255)
email       VARCHAR(255)

orders
------
id          BIGINT PRIMARY KEY
user_id     BIGINT REFERENCES users(id)
status      VARCHAR(30)
total       NUMERIC(12,2)
created_at  TIMESTAMP

Completa la consulta para obtener todos los usuarios, incluyendo aquellos que
no tienen compras aprobadas en los últimos 30 días.

El resultado debe contener:

- user_id;
- name;
- approved_order_count;
- total_spent.

Los usuarios sin compras deben mostrar 0. El resultado debe ordenarse desde el
mayor total gastado hasta el menor.

SELECT
    u.id AS user_id,
    u.name,
    ______________________________ AS approved_order_count,
    ______________________________ AS total_spent
FROM users u
______________________________ orders o
    ON ______________________________
    AND o.status = 'APPROVED'
    AND o.created_at >= CURRENT_TIMESTAMP - INTERVAL '30 days'
GROUP BY ______________________________

Explica:

- por qué elegiste ese tipo de JOIN;
- por qué los filtros de estado y fecha deben colocarse en esa cláusula;
- para qué sirve COALESCE;
- qué sucedería si los filtros se colocaran directamente en WHERE.

RESPUESTA:

SELECT
    u.id AS user_id,
    u.name,
    COUNT(o.id) AS approved_order_count,
    COALESCE(SUM(o.total)) AS total_spent
FROM users u
LEFT JOIN orders o
    ON u.id = o.user_id
    AND o.status = 'APPROVED'
    AND o.created_at >= CURRENT_TIMESTAMP - INTERVAL '30 days'
GROUP BY u.id, u.name
ORDER BY total_spent DESC;

- Se utilizó LEFT JOIN ya que la tarea exigía que se tomaran en cuenta todos los usuarios
con o sin compras y ésta cláusula tomaría en cuenta las filas de la tabla a la izquierda en
este caso users

- Por qué los filtros de estado y fecha deben colocarse en esa cláusula, en este caso la cláusula ON
setea que filas de la tabla derecha (orders) se unen a la tabla de la izquierda (users)

- COALESCE, esta función lo que hace es evaluar un conjunto de parámetros y devuelve el primer valor que no tenga 
valor NULL en este caso funciona porque si los usuarios no tienen compra cuando haga la suma retornaria null, pero
con el COALESCE retorna cero.

- ¿Qué sucedería si los filtros se colocaran directamente en la cláusula WHERE? Si se usara el WHERE los usuario sin 
órdenes serían null y por lo tanto los descartaría al momento de mostrar los resultados y lo que se quiere es mostrar
todos los usuarios.

    CREATE INDEX index_orders_user_approved_created 
    ON orders (user_id, created_at DESC) WHERE status = 'APPROVED';

    -- Indice compuesto completo

    1. user_id
    2. created_at DESC

PREGUNTA 7 — APIS HTTP Y CÓDIGOS DE RESPUESTA
===============================================================================

Explica cómo funciona una API HTTP desde que un cliente envía una solicitud
hasta que recibe una respuesta.

Incluye:

- diferencias entre GET, POST, PUT, PATCH y DELETE;
- qué significa que una operación sea idempotente;
- diferencia entre autenticación y autorización;
- diferencia entre los códigos 401 y 403;
- cuándo utilizarías 200, 201, 204, 400, 404, 409, 422 y 500;
- qué información no debería exponerse en una respuesta de error;
- cómo diseñarías una respuesta JSON consistente para errores.

Incluye ejemplos de:

- una solicitud exitosa;
- un error de validación;
- un intento de acceso sin autenticación.

RESPUESTA:
La API HTTP funciona mediante una petición y una respuesta entre el cliente y el servidor
donde el cliente en su petición incluye el verbo (GET,PUT,POST,DELETE,PATCH), el endpoint,
las cabeceras y el body (si así lo requiere). 
Luego de eso el servidor recibe esa petición la procesa ejecuta lo que deba ejecutar (inserción, modificación o consulta)
y luego envía una respuesta de regreso con un código y la data puede ser un JSON o un XML

- Diferencias entre GET, POST, PUT, PATCH y DELETE
    * GET: se encarga de obtener la información del recurso solicitado, es un método de solo lectura
    por lo tanto no altera el estado del servidor.
    * POST: se encarga de crear un nuevo recurso o procesar información para el servidor (ej: el login de una aplicación)
    * PUT: se encarga de realizar una modificación completa del recurso solicitado
    * PATCH: se encarga de realizar una modificación parcial del recurso solicitado
    * DELETE: elimina el recurso que se especifique en el endpoint
- Qué significa que una operación sea idempotente
    Significa que sin importar las veces que se repita una petición ésta solo alterará el estado del servidor una 
    sola vez por ejemplo las peticiones GET, PUT, DELETE son idempotentes.

- Diferencia entre autenticación y autorización
    La diferencia radica es que mientras la autenticación se encarga de verificar quién es el usuario,
    la autorización se encarga de verificar qué tiene permitido hacer ese usuario que ya está verificado.

- Diferencia entre los códigos 401 y 403
    * La 401 indica que la petición/solicitud no tiene las credenciales ya sea porque el usuario no está logueado 
    o su token de acceso está vencido.
    * La 403 indica que si bien el usuario está autenticado no tiene los permisos necesarios para acceder a ese recurso.

- Cuándo utilizarías 200, 201, 204, 400, 404, 409, 422 y 500
    * 200: Cuando la petición fue creada con éxito por ej en una petición GET 
    * 201: Cuando la peticón ha tenido éxito y se ha creado un nuevo recurso ej. una petición POST
    * 204: Este se utiliza cuando la petición tuvo éxito pero el servidor no retorna nada, ej una petición DELETE
    * 400: Cuando el servidor no logra procesar la solicitud debido a un error ejemplo JSON mal formado o 
    parámetros mal estrcuturados
    * 404: El recurso que se solicita no existe
    * 409: Cuando hay un conflicto un conflicto con el estado actual del servidor ejemplo registrar un correo existente
    * 422: Ocurre cuando la petición está bien formada, pero hay errores de validación como cuando no se llenan valores requeridos.
    * 500: Ocurre cuando hay un fallo inesperado no controlador por el servidor.

- Qué información no debería exponerse en una respuesta de error
    *Ni contraseñas, tokens o credenciales
    *Rutas internas del servidor
    *Consultas SQL crudas o nombres de tablas.

PREGUNTA 8 — ¿CÓMO APRENDE UNA RED NEURONAL?
===============================================================================

Explica con tus propias palabras qué significa entrenar una red neuronal. Describe 
un ciclo de entrenamiento desde que la red recibe datos hasta que ajusta sus parámetros. 
Incluye qué papel cumplen la predicción, la función de pérdida y la retropropagación.

RESPUESTA:
Las RNA se entrenan ajustando sus parámetros internos usando un conjunto de datos de ejemplo
ya que estos no se entrenan con con reglas fijas sino que ésta se va ajustando hasta ir obteniendo el 
resultado deseado.

Un ciclo de entrenamiento, va desde:
    1. La recepción de los datos, en donde la información fluye para que cada neurona se multiplique esa data
    por el peso y el sesgo
    2. Cálculo de error, acá después de la predicción hay una función que compara la predicción con la respuesta desplegada
    3. Distribución del error, acá se trata de mitigar el error hacia atrás 
    4. Ajuste de parámetros, en esta parte el algoritmo optmiza y modifica los sesgos y los pesos buscando así reducir el margen de error

¿Qué se entiende por procesamiento del lenguaje natural (PLN) y en qué se diferencia
